### Задание 1

Напишите запрос к учебной базе данных, который вернёт процентное отношение общего размера всех индексов к общему размеру всех таблиц.

#Решение

SELECT 
    ROUND(SUM(index_length) / SUM(data_length + index_length) * 100, 2) AS 'Процент индексов от общего размера'
FROM 
    information_schema.TABLES 
WHERE 
    table_schema = 'sakila';
	
Этот запрос суммирует длину данных (data_length) и длину индексов (index_length) для всех таблиц в схеме sakila, после чего вычисляет процентное отношение размера индексов к общему размеру 

### Задание 2

Выполните explain analyze следующего запроса:
```
select distinct concat(c.last_name, ' ', c.first_name), sum(p.amount) over (partition by c.customer_id, f.title)
from payment p, rental r, customer c, inventory i, film f
where date(p.payment_date) = '2005-07-30' and p.payment_date = r.rental_date and r.customer_id = c.customer_id and i.inventory_id = r.inventory_id
```
перечислите узкие места;
оптимизируйте запрос: внесите корректировки по использованию операторов, при необходимости добавьте индексы.

#Решение
Исходный запрос имеет несколько серьезных проблем с производительностью:

Использование функции DATE() в условии WHERE: Выражение date(p.payment_date) = '2005-07-30' делает невозможным использование индекса по столбцу payment_date. MySQL будет вынужден выполнить полное сканирование таблицы payment, применяя функцию к каждой строке .

Избыточные соединения (лишние таблицы): Запрос соединяет пять таблиц, но для конечного результата (имя клиента и сумма его платежей за день) нужны только payment и customer. Таблицы rental, inventory и film участвуют в соединении и оконной функции, но не добавляют полезной информации, а лишь многократно увеличивают количество обрабатываемых строк и стоимость запроса .

Неявный синтаксис JOIN: Использование запятых в FROM для соединения таблиц устарело и затрудняет чтение, хотя сам по себе это не главная проблема производительности.

Оптимизированный запрос:
```
SELECT 
    CONCAT(c.last_name, ' ', c.first_name) AS customer_name,
    SUM(p.amount) OVER (PARTITION BY c.customer_id) AS total_amount
FROM 
    payment p
INNER JOIN 
    customer c ON p.customer_id = c.customer_id
WHERE 
    p.payment_date >= '2005-07-30 00:00:00' 
    AND p.payment_date < '2005-07-31 00:00:00';
```	
изменения:

Удалены лишние таблицы: Мы исключили rental, inventory и film. Данные о платежах (payment) уже содержат customer_id, поэтому мы можем напрямую соединить payment с customer.

Оптимизировано условие по дате: Вместо применения функции к столбцу, мы сравниваем payment_date с диапазоном. Это позволяет оптимизатору использовать индекс по payment_date для быстрого поиска нужных строк .

Скорректирована оконная функция: Поскольку таблица film удалена, раздел PARTITION BY теперь использует только c.customer_id. Логика подсчета суммы для каждого клиента за день сохраняется.

Рекомендуемый индекс:

Для максимальной производительности этого запроса убедитесь, что в таблице payment существует индекс по столбцу payment_date.
```
CREATE INDEX idx_payment_date ON payment(payment_date);
```
Этот индекс позволит быстро отфильтровать строки за нужный день без полного сканирования таблицы .
